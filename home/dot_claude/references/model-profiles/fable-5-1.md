# Fable 5.1 prompting profile

Model id: claude-fable-5-1 (shares weights with claude-mythos-5-1) Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-fable-5-1 + https://platform.claude.com/docs/en/models/fable-5-1/whats-new-fable-5-1 Distilled: 2026-09-17

Re-distill when the source doc changes or this date is older than ~6 months.

## Params (set these, don't reproduce their effect in prose)

- effort: default `high`. Re-run the sweep — level names don't map to the same thinking volume as Fable 5. `medium` ≈ Fable 5 quality at lower cost; `low` is often cheaper per task than Opus/Sonnet at higher effort while scoring higher, so include it wherever a smaller model was the plan. Two effort-coupled behaviors: `low` under-triggers search; `xhigh`/`max` may draft a long deliverable in thinking and then write it again — run long deliverables at `high` unless a measured gain justifies more, and if not, set `max_tokens` for thinking + reply and append the budget note (Keep/add).
- thinking display: progress notes between tool calls arrive as `thinking` blocks and are empty under the default `display: "omitted"`. Set `"updates"` (beta `thinking-display-updates-2026-08-18`) or `"summarized"` before adding any progress-update prompt line.
- history: append-only. Thinking blocks are bound to the exact conversation (enforced for accounts created on/after 2026-08-31; prefix change → 400, or `thinking.block_binding.prefix_mismatch_behavior: "drop_block"` under beta `thinking-binding-controls-2026-08-01`). Per-turn reminders go in turn-scoped system messages (`clear_at: "next_user_message"`, beta `mid-conversation-system-clear-at-2026-08-21`); leave cleared copies in place byte-for-byte. Client-side compaction = one summary message + the new user turn, nothing replayed. Cache reads are cheaper, so test later compaction points.
- safeguards: classifiers can return `stop_reason: "refusal"`. Fewer false positives than Fable 5, but still: ask "are there any bugs" rather than "does this compile", give docs for lesser-known languages, keep base64 out of tool output.

## Remove — scaffolding this model makes redundant or harmful

| pattern in config                                                                     | why remove                                                                                                                                                                                       |
| ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| anti-formatting rules written for earlier models ("no bullets", "avoid bold in chat") | 5.1 already under-formats: less bold, fewer headers/lists/quotation marks. Replace with a when-formatting-helps rule (Rewrite)                                                                   |
| narration suppressors ("hold all findings for the final response")                    | 5.1 writes fewer user-facing updates than Fable 5 by default, more so at high effort and in long tool chains; a suppressor compounds it. Delete before adding any progress prompt                |
| harness logic that blocks the lead agent until each subagent returns                  | letting the lead continue lowers average completion time at similar quality/cost. Spawn returns immediately, results arrive in a later `user` message, a separate tool waits when the lead wants |

| from                                  | to                                                                                                                                                                                                                                                                                                                                                                                                                                                               | why                                                                                                                                                                       |
| ------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| "be concise" / "write simply"         | name the anti-pattern: _mannered prose_ substitutes metaphor and flourish for direct statement ("a dial worth turning" for "a parameter worth varying", "earns its keep" for "still matters"); say what you mean, use the literal phrase when one exists. Short form: "Please remove all mannered prose." Prefer a user message over the system prompt                                                                                                           | 5.1 has fewer stock phrases than earlier models but runs denser: longer sentences, fewer paragraph breaks. Defining the anti-pattern works; generic brevity asks don't    |
| bans on lists/bold                    | "Use lists and bullet points when asked to, or when the content is multifaceted enough that they help with clarity. If the person explicitly requests minimal formatting, honor it. In conversational, personal, or emotional exchanges, keep to plain prose."                                                                                                                                                                                                   | positive trigger conditions replace a ban the model no longer needs                                                                                                       |
| "don't stop early" / "keep going"     | the autonomy block: open with "You are operating autonomously. The user is not watching in real time and cannot answer questions mid-task" (this sentence carries most of the effect — keep it verbatim), proceed on reversible actions, stop only for destructive actions or genuine scope changes; exception: a described problem or question gets an assessment, not a fix; before ending, if the last paragraph is a plan/question/promise, do that work now | 5.1 otherwise narrates the next step ("Next, I'll…") or asks "Shall I…?" for work already requested. Side effect: fewer questions on ambiguous asks — check the trade-off |
| implicit deliverable scope            | the "Delivering work" block: the request (or approved plan) sets the scope and the scope is the deliverable; make routine judgment calls; do everything that doesn't depend on an open question first, then state the assumption; a blocked part is reported, the rest delivered in full; a decided step is run, not announced                                                                                                                                   | pairs with the autonomy block; if prompt length is tight keep only the autonomy block                                                                                     |
| implicit change scope in coding tasks | pre-existing bugs / perf / unmentioned behavior → report as follow-up, don't fix unless the requested behavior can't work without it; ambiguity → the reading the wording and surrounding code most directly support, stated in the summary; commit tests only where the task asks or the repo already keeps tests for this kind of change, sized like neighbors, scratch checks not promoted to test files                                                      | unrequested additions and committed test files drop substantially with no change in task success                                                                          |
| nothing about edit style              | "The number of tokens used to edit files is best minimized, all else being equal. Therefore, when it will not affect the end result, try to surgically edit a file rather than rewrite the entire thing."                                                                                                                                                                                                                                                        | 5.1 rewrites whole files for small changes more than Fable 5; same result, more output tokens and time                                                                    |
| "summarize the document"              | one complete example in the system prompt: request, response, and a rationale sentence explaining that each source is conveyed in the assistant's own indirect speech with any lifted phrase marked as a quotation; template the tool-call lines with your tool's name                                                                                                                                                                                           | 5.1 reproduces source passages unmarked more often than Fable 5                                                                                                           |
| generic client-side compaction prompt | the six-item preserve list: problems and how handled; options tried/set aside and why; anything asked, decided, ruled out, or set as constraint — stated exactly; where things stand; what is open or promised; hard-to-reconstruct details (names, numbers, dates, wording, links). Keep the user's words close; condense the model's own reasoning                                                                                                             | 5.1 responds well to an explicit retain list; without it, constraints and rejected options drop and get re-proposed                                                       |

## Keep / add

| pattern                                                                                                                                                                                                                                                                  | why                                                                                                                                                             |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| progress cadence (human-in-the-loop only): one line on what you're about to do; brief updates while working; close with a recap that stands on its own — found, did, next                                                                                                | only after fixing thinking display and removing suppressors; otherwise the updates may already exist but never reach the UI                                     |
| batch nudge as a turn-scoped system message after every tool result: "First privately list what you need next; then request every item that doesn't depend on another's result in this one response." (no beta: a text block after the `tool_result`s)                   | 5.1 parallelizes explicitly named fetches fine; it serializes in coding/computer-use loops where the next calls are implied. Each extra turn costs a round trip |
| tool-output visibility note when the UI collapses output: "Only you see that command's output — the user's terminal shows at most a few lines of it. If the user needs to read any of it, put it in your reply." (turn-scoped)                                           | otherwise the model runs commands to "show" output the user never sees                                                                                          |
| search trigger at `low` effort: a name you don't confidently recognize, or one from a fast-moving area (AI models, developer tools), is the thing to verify — search before answering, include the name as the user wrote it; partial background is not a reason to skip | or raise effort for just the affected turns                                                                                                                     |
| long-output budget note at `xhigh`/`max`: everything in one reply including reasoning counts toward ~[max_tokens]; drafting the deliverable in thinking and again in the reply doubles the turn; use reasoning to settle structure and inputs, the output space to write | cuts thinking length on prose and code requests; replace `[max_tokens]` with the real value                                                                     |
| vision: an agent with a container holding the raw images and PIL/OpenCV, or at minimum a crop-and-enlarge tool (https://platform.claude.com/cookbook/multimodal-crop-tool)                                                                                               | 5.1 does its best vision work iterating analyze → crop → verify; cropping scales test-time compute with image tokens                                            |

## Already supplied by the Claude Code harness
