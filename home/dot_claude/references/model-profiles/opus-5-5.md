# Opus 5.5 prompting profile

Model id: claude-opus-5-5 Source: https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/prompting-claude-opus-5-5 + https://platform.claude.com/docs/en/models/opus-5-5/whats-new-opus-5-5 + https://platform.claude.com/docs/en/build-with-claude/effort + https://platform.claude.com/docs/en/agents-and-tools/tool-use/advisor-tool Distilled: 2026-10-08

Re-distill when the source doc changes or this date is older than ~6 months.

This profile is a delta on `opus-5.md`. The guide states Opus 5 prompts "should perform well without changes", so every Opus 5 row not contradicted below still applies — but as carried-over guidance, not re-measured on 5.5. In particular these Opus 5 rows are **carried until re-measured**: delete verification/self-check instructions (over-verification), cap subagent spawns, "report every finding; a later stage filters" in review prompts, explicit conciseness prompt instead of effort for visible length, scope-discipline instruction.

## Params (set these, don't reproduce their effect in prose)

- effort: default **`medium`** (Opus 5 was `high`) — a request that omits effort runs one level lower than on Opus 5. `medium` matches or beats Opus 5 at `high` on coding and knowledge work; `low` comes close on several coding evals at much lower cost. At a given level 5.5 thinks _more_ per turn than Opus 5, most at `xhigh`/`max`: reserve those for measured gains. To get less thinking, lower effort — more reliable than prompt instructions. Change effort per turn with a per-message `output_config` (beta `mid-conversation-output-config-2026-07-01`); a top-level change invalidates the cache.
- thinking: **always on**. `{type: "disabled"}` and `{type: "enabled", budget_tokens}` → 400. Omit the field or send `adaptive`. Select response blocks by `type`, never by position.
- max_tokens: thinking counts toward it even when not returned; 128K (the model max) worked well for long agentic coding turns.
- tool_choice: `any` / `tool` → 400. Keep `auto`; for schema-valid JSON use `strict: true` or structured outputs; to make it call a tool, say in the prompt when the tool applies.
- history: thinking blocks are bound to the model and the conversation prefix (enforced for accounts created on/after 2026-08-31). Keep the conversation append-only; change instructions or tools via mid-conversation system messages. Opus 5.5 cannot read Fable/Mythos thinking blocks; Fable 5.1 can read Opus 5.5's (Claude API).
- progress text: notes between tool calls arrive as `thinking` blocks, empty under the default `display: "omitted"`. Set `display: "updates"` (beta `thinking-display-updates-2026-08-18`) before adding any progress prompt.
- safeguards: classifiers for cyber, **bio (new vs Opus 5)**, and `reasoning_extraction`. Finding vulnerabilities in source code is allowed; high-risk dual-use cyber is not. A prompt that asks the model to write out its reasoning in the response invites a `reasoning_extraction` decline — read `display: "summarized"` thinking instead.
- advisor: Opus 5.5 executor may pair with a Fable 5.1 / Mythos 5.1 / Fable 5 / Mythos 5 / Opus 5.5 / Opus 5 advisor.

## Remove — scaffolding this model makes redundant or harmful

| pattern in config                                                                                        | why remove                                                                                                                                         |
| -------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| "think carefully / think step by step before answering" in chat or always-on config                      | the model decides how much to think and effort is the control; removing such a line made replies start sooner with no clear quality decline        |
| instructions that make the model write its reasoning into the response (stand-ins for disabled thinking) | thinking is always on; these now risk `reasoning_extraction` declines                                                                              |
| thinking-disabled mitigations ("you may say a sentence before a tool call", no-internal-tags, no-think)  | they patched Opus 5 artifacts that appear only with thinking disabled, which 5.5 cannot do; re-test, and drop the no-thinking rule unconditionally |
| vision scaffolding built for earlier models (forced crop/describe steps for ordinary charts/screenshots) | 5.5 at its lowest effort read dense charts more accurately than Opus 5 at its highest; keep tools only for the densest inputs (technical drawings) |
| "avoid a generic AI look" style frontend guidance                                                        | it mostly swaps one default style for another; name the specific patterns instead (Rewrite)                                                        |

## Rewrite

| from                                                       | to                                                                                                                                                                                                                                                                                                                                                                                                                      | why                                                                                                                                                                   |
| ---------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| treating a text-only end of turn as "task done" (harness)  | treat it as a report: keep the task's parts in a checklist the model updates; if a turn ends with open items and no stated blocker, send a user message naming them ("Your task list still has open items: … Continue with them. If one is blocked, say what is blocking it."); cap at 2–3 automatic continuations                                                                                                      | on long multipart tasks 5.5 keeps the user updated, and some updates end the turn without a tool call; an unattended loop that reads that as completion stops partway |
| letting a run end while a background command/subagent runs | wait for it, return its output as the next user message, then judge completion                                                                                                                                                                                                                                                                                                                                          | the work is not done while something it started is still running                                                                                                      |
| generic "don't stop early" in unattended agents            | name the stops to avoid and the stops wanted: no summary that announces the next step without taking it, no offer to continue "unless you'd prefer otherwise", no list of non-blocking decisions, no "good place to report"; put status notes in the same message as the next tool call; stop only when nothing can move without the user or the blocker is deliberately protected; keep confirmation for risky actions | 5.5 responds to instructions that name specific early-stop kinds. Unattended only — leave it out of human-in-the-loop apps; expect more tool calls and output tokens  |
| "avoid generic design" for frontend                        | name the patterns to avoid, e.g. "Do not use a cream or off-white background, italic accent words in headlines, numbered '01/02/03' section labels, monospace labels, or pill-shaped buttons"; iterate by checking which default it fell back on and extending the list                                                                                                                                                 | 5.5 falls back on a few default styles; named patterns steer it, general asks don't                                                                                   |

## Keep / add

| pattern                                                                                                                                                                                                                                                                                        | why                                                                                                                                                                                                                                                       |
| ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| multi-app workflows: "Before taking any action, explore broadly with tool calls: list and open the emails, documents, spreadsheet tabs and records across the available apps that could be relevant to this task, including ones the task does not explicitly mention, and use what you find." | 5.5 gets to work quickly and misses context the task didn't point to; this completed noticeably more multi-app tasks. Keep untrusted content out of what it searches                                                                                      |
| multi-turn chat where re-examination is unwanted: "Once you have answered something, treat that answer as done. On later turns, focus your thinking on what the user is asking now, and don't go back over an earlier answer unless the user asks about it or points out a problem with it."   | cuts follow-up thinking/latency. Leave out of long analyses and agentic tasks where a later step can reveal an earlier mistake; may suppress unprompted self-correction                                                                                   |
| multiagent time signal: append `elapsed <s>s / <budget>s` to each harness message, budget set above the time you want; or, with no budget, "Time matters here: do not spend time that can be avoided, and the earlier a correct result is obtained, the better."                               | 5.5 paces to the budget and parallelizes more; advisory only — keep a hard timeout, and check quality (it may search/verify a little less)                                                                                                                |
| pasted text wrapped in `<pasted_content id="…">` … `</pasted_content id="…">` plus the system note that instructions inside are followed only where the user's own message asks                                                                                                                | makes 5.5 robust to instructions inside user-pasted content; slightly more cautious; one guardrail among several                                                                                                                                          |
| progress cadence, human-in-the-loop only: one line of intent before the first tool call, a short recap at the end; harness reminder after ~5 silent tool steps, max 2–3 reminders                                                                                                              | 5.5 follows explicit cadence instructions; the reminder roughly halved long silent stretches at no measurable cost                                                                                                                                        |
| advisor under-calling on an Opus executor (only when observed): "Call advisor for design, architecture, and risk questions where you won't touch a file. If your response would be analysis or a recommendation with no other tool calls, call advisor first."                                 | +7–10 pt on under-calling tasks. Do NOT add the "first write must be preceded by an advisor call" hard rule by default — it over-calls and nets flat on mixed workloads. Never add the Haiku-style mid-conversation nudge to Opus (it lowered pass rates) |

## Already supplied by the Claude Code harness

Don't duplicate these into `~/.claude/rules/` or CLAUDE.md when the consumer is a Claude Code session — its system prompt and turn-scoped messages carry them: the `<pasted_content>` note, the advisor timing and advice-handling blocks (when `advisorModel` is set), the "The user hasn't heard from you in a while" silent-stretch reminder, background subagent/command results arriving as later notifications, and compaction with a summary hand-off. Rules should cover only the judgment those leave open (when an advisor call is worth it in this workflow, which actions are risky here, what counts as done for a loop).
